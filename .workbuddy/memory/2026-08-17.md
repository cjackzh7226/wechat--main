## “5/6 正在理解图片”停留诊断

- `5/6` 状态只在 `main.py::_process_window` 调用 `VisibleContentAnalyzer.analyze` 前设置；该分析器一旦认为截图可能含图片，会在监控线程中同步请求视觉模型，单次 HTTP 超时为 20 秒。请求期间 UI 仍可响应，但状态不会前进，因此表现为卡在 5/6。
- 可见内容判断把“截图中非白色/彩色区域占比 >= 8% 且 OCR 有效行不多”作为图片候选。用户截图里的大块蓝色长文字气泡满足“大可见图像区域”，存在被当成图片的风险；对同一截图的隔离重放得到 `LARGE_REGION=True`。现场截图重放 OCR 得到 7 行时不会调用视觉模型，但实时 OCR 的行数波动到 3 行及以下就会触发，说明该门槛对长气泡不稳定。
- 昂贵的视觉分析发生在“上下文是否与上次相同”的判断之前；若视觉接口慢或不可达，同一未变化聊天仍会每轮重复进入最长 20 秒等待，形成持续 5/6。失败信息只保存在 `visible_analyzer.last_error`，有文字上下文时不会直接显示，所以用户看不到是在等待还是接口失败。
- 另有顺序缺陷：监控循环先按旧 `current_chat_type` 执行 `_process_window`，之后才由 `_conversation_list_bypass` 读取顶部标题并刷新群聊/个人类型。用户从个人会话切进群聊的第一轮仍会错误执行个人会话的图片理解；若这里进入视觉请求，群聊类型刷新也被同步阻塞。
- 使用用户提供截图做隔离 OCR/条件重放，没有读取正式设置、API Key、聊天文件或发送台账。本轮按“为什么”只完成诊断，未修改源码、EXE 或正式数据，未 commit、未 push。
