# 2026-08-03 普通话术库匹配分叉分析与"共享打分+阈值"方案预演

> 背景：用户反馈"管理话术 > 测试命中"第一位总能排中，但运行时匹配不一致。
> 本文记录分析结论与阈值预演数据，为后续统一方案提供依据。只读验证，未改代码。

## 一、确认的事实（读码 + 只读实测）

- 测试命中页（普通话术库）用 `memory.scored_examples()`：
  `score = 关键词∩cue×16 + 关键词∩reply×8 + 向量余弦×45 + 意图×6 + 优先级×0.22`，全量排序、展示 top200、不过滤、recent 兜底（无命中时仍显示低分条目）。
- 运行时话术库兜底用 `memory.strict_relevant_examples()`：
  `score = 整段对话∩cue×3 + ∩reply×1 + 最后句∩cue×4 + 意图 + 优先级/10`，关键词为主、**向量只补名额（阈值 0.08）、不参与排序**；再经 `_quality_filter` 过滤。
- model_memory 模式下话术库只是第二顺位兜底：有 API Key 先模型，失败/无 Key 才 `_fallback() → _memory_replies()`。
- 分叉实证（90 条企业内容改普通话术源模拟）：
  - `我之前交的东西在哪看` → 测试页第一=「退回问题在年检填报系统…」(25分)，运行时第一=「社会团体、民办非企业年检期间…」**不一致**。
  - 含强关键词问法（年报/报告）两套函数结果一致；纯语义模糊问法才会分叉。
- "测试页第一位总能排中"的 4 个原因：①向量权重 45/100 全量参与排序（2/3/4-gram 哈希向量可跨词面召回）；②测试页输入是干净单句，运行时是整段对话词元被稀释；③测试页不过滤；④recent 兜底让测试页"总有第一条"。

## 二、用户确认的新需求

- 运行时像测试命中页一样：按匹配值从高到低选最匹配的一条回答；
- **第一名匹配值 < 30 分 → 视为知识库未准备该类问题，老实回答"不知道"（不硬答、不编造）**。

## 三、30 分阈值预演结果（90 条模拟普通话术，scored_examples 第一名）

| 问法 | 分数 | >=30 判定 |
|---|---|---|
| 年度工作报告在哪里找 | 100 | 发送 |
| 年度报告怎么打印 | 86 | 发送 |
| 怎么看我上一年度的公示情况 | 74 | 发送 |
| 年检时间什么时候 | 58 | 发送 |
| 查一下往年的材料 | 45 | 发送 |
| 之前那个报告怎么看 | 34 | 发送 |
| **年报在哪里找** | **24** | **答不知道（疑似误伤，措辞敏感）** |
| 年终总结怎么写 | 26 | 答不知道 |
| 我之前交的东西在哪看 | 25 | 答不知道 |
| 今天天气怎么样 / 你吃饭了吗 / 帮我写一首诗 | 25/10/10 | 答不知道 ✅ |
| **想查一下之前的年报** | **18** | **答不知道（企业库正例在普通话术打分下误伤）** |

结论：30 阈值能正确拦截无关问法，但对措辞敏感的模糊问法（"年报在哪里找"24、"想查一下之前的年报"18）存在**误伤可答问题**的风险。阈值需结合用户真实话术库验证/调整（如 20），不能拍脑袋。
注意：用户当前真实 memory.json 只有 1 条话术（福宝放哪里→放客厅正南方），实施后除强相关问法外基本都会答"不知道"，需先导入足够训练话术才有意义。

## 四、拟定改造方案（待用户确认后实施）

1. `memory.py` 新增共享入口 `phrasebook_candidates(conversation_text, limit)`：内部 `_last_other_text()` 提取对方最后一句作 query，走 scored_examples 同款打分，标注 `phrasebook_score`。
2. `reply_engine.py _memory_replies()` 改用共享打分；`generate()/_fallback`：top>=阈值返回候选；有条目但 <阈值 → 固定"不知道"文案；知识库空 → 原模型/本地规则。
3. `main.py _select_managed_reply`：话术库来源直接取第一名，不再二次重排。
4. `tests/test_core.py` 先写"测试页第一名=运行时第一名"回归测试，再改代码，复跑 220+。
5. 阈值：建议先用回归测试锁定，按真实话术库样例微调（30 或 20）。
