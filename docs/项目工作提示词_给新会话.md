## 一、项目是什么

**聊小智**是一个企业微信自动回复/客服助手。它通过截图 + OCR 识别企业微信聊天窗口的对话内容，用话术库/企业库/模型/知识库生成回复，并自动发送。

- **宿主平台**：企业微信（**只认企业微信，微信/QQ 不处理**，见 `wechat_window.py::_match_platform`）
- **用户企业微信版本**：**5.0.9.6060**（代码注释里写的 4.x 已过时，所有比例/颜色/布局常量必须实测重定，不能照搬旧注释）
- **用户企业微信账号名**：程正恒（群聊 @ 识别用）

## 二、技术栈与运行环境

- **Python 3.11.9**（`.venv` 虚拟环境）
- **截图**：`win32gui` + `PrintWindow`（`capture_ocr.py::_capture_window_bitmap`，可抓遮挡窗口）
- **OCR**：`rapidocr-onnxruntime`（`ChatOCR` 类）
- **点击/发送**：`pyautogui` + `pyperclip`（`sender.py::WeChatSender`）
- **窗口检测**：`win32gui` / `win32process`（`wechat_window.py::ChatWindowDetector`）
- **UI**：`tkinter`（`float_ui.py`，悬浮窗）
- **视觉模型**（可选）：智谱 GLM-4V（`visible_content.py`，识别图片/卡片/表情）

## 三、项目架构概览

### 核心文件

| 文件 | 职责 |
|---|---|
| `main.py` | 主程序入口，`_monitor_loop` 轮询 + `_process_window` 处理 + 托管发送 + 会话列表旁路 |

| `wechat_window.py` | 企业微信窗口检测（只认 wecom） |

| `reply_engine.py` | 回复生成决策链（**末尾 `_readable_*` 版本覆盖旧函数，改逻辑必须改 readable 版本**） |
| `memory.py` | 匹配决策核心：企业库 `enterprise_candidates` + 话术库 `phrasebook_candidates` |
| `enterprise_kb.py` | 企业知识库 |
| `settings.py` | `AppSettings` dataclass，持久化到 `%APPDATA%\WeChatStyleReplyAssistant\settings.json` |
| `float_ui.py` | tkinter 悬浮窗 UI |
| `visible_content.py` | 可见内容分析（表情/图片/卡片/链接），可选调视觉模型 |
| `conversation_list.py` | **新功能**：左侧会话列表红点检测 + 四分类 + 状态机 |
| `group_chat_handler.py` | **新功能**：群聊 @ 识别 + 发送者名字提取 + 回复构建 |

### 回复生成决策链（`generate()`）

```
企业库高置信直发 / 范围未命中固定文案
  → 话术库（memory/model_memory）
    → 模型
      → 知识库有条目但低分 → "暂时未查到对应答案。"
        → 空库走本地规则
```

### 阈值常量（`memory.py`，改前必须先写测试）

- `ENTERPRISE_LOCAL_CONFIDENT_FLOOR = 20`（企业库可靠底线）
- `ENTERPRISE_LOCAL_CONFIDENT_MARGIN = 8`（明显领先差距，**并列/接近必须拒答，不能去掉**）
- `PHRASEBOOK_CONFIDENT_SCORE = 20`（普通话术库最低匹配值）

### 数据目录（重要，不互通）

- **源码模式**（`启动.bat`）：读 `%APPDATA%\WeChatStyleReplyAssistant\`（settings.json / memory.json / vector_memory.json）
- **EXE 模式**（frozen）：读 `EXE目录\user_data\`
- **两套数据不互通**，换包需重新导入或复制 user_data

## 四、已实现的功能

### 功能 A：核心回复引擎（长期存在）

- `_monitor_loop` 每 `poll_interval_ms`（默认 1200ms，群聊 800ms）轮询
- 优先取前台窗口，前台不是企业微信时回退 `any_chat_window()`
- `_process_window`：截图 → OCR → 判断最新消息角色 → 托管模式下生成回复 → 发送
- 托管模式有回声等待（`managed_waiting_for_own_echo`）、turn 管理、发送中保护（`managed_send_inflight`）

### 功能 B：左侧会话列表自动切换 + 四分类（2026-08-07 实现）

**触发**：托管模式 + 最新消息为我方发出 + 持续 2 秒 → 扫描左侧列表（每 2 秒一次）
**6 种打断**：最新消息变对方 / 用户输入中(焦点在输入框+1.5s内有键盘) / 发送中 / 处理中 / 企业微信不在前台 / 切换重试中
**切换**：选第一个红点（从上到下，y 最小）→ pyautogui 点击头像区 → 等 1.2 秒 → 顶部标题变化+红点消失双重确认 → 失败重试 1 次 → 连续 3 次失败：UI 正中央+置顶+系统提示音+暂停 5 分钟
**四分类**（`ConversationTypeDetector`）：
- `system`（系统号）：顶部标题 OCR 命中白名单/关键词 → **跳过不回复**
- `group`（群聊）：头像 3×3 子块**边界主色跳变**（非整体色彩丰富度，规避合影头像陷阱）→ 群聊客服分支
- `personal`（个人）：单方块头像 → 现有主程序
- `unknown`：跳过 + 提示

**关键改造**：同窗口切会话 hwnd 不变，用**顶部标题文字**作会话标识（`ChatIdentityTracker`，替代 `window_key`）；新增旁路接入 `_monitor_loop`，**主路零改动**。

**实现位置**：`conversation_list.py` + `main.py::_conversation_list_bypass / _bypass_try_switch / _after_switch / _show_bypass_alert`
**实现说明**：`docs/会话列表自动切换_实现说明_20260807.md`

### 功能 C：群聊专属问答客服（2026-08-07 实现）

**UI**：`float_ui.py` 模式行下方新增"当前账号用户名"输入框（`settings.wecom_account_name`，首次空弹提示，持久化）
**核心逻辑**：群聊消息开头 @ 当前账号用户名 → 走回复；没 @ → 认定"聊天内容无变化"不回复
- @ 是**黑色文字**（非蓝色），OCR 无障碍；容错匹配（去空格标点后比较）
- 发送者名字 = 灰色名字 + 绿色平台标记（`@微信` 等），字符串规则去标记后缀得纯名字
- 回复 = **文字 @**（非真 @ 提醒），格式 `@发送者名字 回复内容`，复用 `sender.py`
- 话术复用现有企业库/话术库/模型/知识库
- 群聊 OCR 间隔：1200ms → 800ms（`settings.group_poll_interval_ms`）
- 触发扫描扩展：群聊无 @ = 聊天内容无变化，等同"我方发出"待遇；@ 我时不触发扫描（走回复）
- @ 被覆盖接受漏掉（最新消息为准）；群聊上下文只取 @ 我那条（不取前文）

**实现位置**：`group_chat_handler.py` + `main.py::_handle_group_chat` + `float_ui.py` 用户名输入框
**实现说明**：`docs/群聊客服功能_实现说明_20260807.md`

## 七、关键坑与陷阱

1. **5.0.9.6060 vs 4.x**：代码注释里的 4.x 比例/颜色/布局常量已过时，必须实测重定。
2. **九宫格检测陷阱**：群聊头像判定必须用"3×3 子块**边界主色跳变**"，**绝不能用整体色彩丰富度**——否则合影头像（一张图里多人）会误判成群聊。
3. **同窗口切会话 hwnd 不变**：企业微信切会话主窗口 hwnd 不变，`window_key=(hwnd,title)` 去重失效，必须用顶部标题文字作会话标识。
4. **EXE vs 源码数据不互通**：源码读 `%APPDATA%`，EXE 读 `EXE目录\user_data\`，换包需复制数据。
5. **current_context 恒空坑**（已修）：旁路不能依赖 `self.current_context` 判断最新消息角色（主路只在 auto_recognize/training_mode 下刷新它），托管模式下恒空。旁路必须**自己截全窗图 + OCR**判角色。
6. **工具栏红点角标误扫**（已修）：企业微信最左侧工具栏的"消息"图标有红点角标，会被误当会话红点。红点扫描区域必须从 x=0.08 起（跳过工具栏）。
7. **@ 是黑色文字**（群聊）：不是蓝色，OCR 识别无障碍。@ 在消息开头才算，中间的 @ 不算。
8. **发送者名字 vs 平台标记**（群聊）：灰色是名字，绿色是平台标记（`@微信` 等），必须用字符串规则去标记后缀，不能用颜色判断（颜色受主题/版本影响）。
