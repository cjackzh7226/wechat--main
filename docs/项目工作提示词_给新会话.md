# 聊小智项目交接（给零上下文新会话）

最后更新：2026-08-16。当前事实以本文件、当日 `.workbuddy` 日志、最新阶段报告和当前测试结果为准；2026-08-15 以前关于旧发布候选、待正式迁移、自由生成、便携 `user_data` 和覆盖旧包的说法均已失效。

## 1. 产品合同

- 宿主平台：企业微信 5.x；只处理企业微信。
- 自动回复只能发送：
  1. 当前有效且来源完整、分区无冲突的知识记录答案原文；或
  2. 精确固定文案 `暂未查到对应答案`。
- 大模型仅允许做候选排序/一致性判断，不得生成、补写、改写或润色自动发送正文。
- 同一问题的答案按 `social`（社团）、`mfei`（民非）、`both`、`unknown` 分区；同分区不同答案进入 conflict，不可自动发送。
- 候选最低分 30、领先差 8；发送前必须重新读取记录并核对 ID、答案哈希和答案原文。
- 长文本答案逐字保留，不强制分块，不压平空行。

## 2. 正式数据与启动入口

- 源码和 EXE 都使用 `%APPDATA%\WeChatStyleReplyAssistant`；可用 `WECHAT_ASSISTANT_DATA_DIR` 显式覆盖到测试/staging 根。
- 正式目录包含 settings、DPAPI credentials、memory、vector、send ledger、logs；禁止打进 EXE。
- `启动.bat` 仅供源码开发。
- 正式用户入口是版本化 onedir 中的 `聊小智.exe` 或指向它的桌面快捷方式。
- 当前发布候选：`dist\聊小智_2026.08.16.4\聊小智\聊小智.exe`；桌面 `聊小智.lnk` 已指向该文件。
- 发布包不包含 `user_data`，不得复制或提交正式凭据/聊天/日志。

| `candidate_judge.py` | 模型严格 JSON 候选一致性判断，不接收答案正文 |

| `managed_runtime.py` | 一个有界队列、一个非 daemon worker、一个串行发送协调器 |
| `send_ledger.py` | 持久幂等账本：prepared/keypress/verified/uncertain/failed/baseline |

## 4. 托管运行时安全边界

- 模式内部键：`off`、`observe`、`controlled`、`full`；界面统一显示“关闭、观察、受控、全托管”。
- `observe` 做匹配、裁决、实时预检，但绝不调用 sender。
- `controlled` 只允许显式白名单聊天；当前正式配置使用 `full`，个人和群聊均无需逐个加入白名单，但仍受相同前台/身份/问题/账本门禁。
- 个人和群聊共用唯一串行 worker。自动发送前重新直接捕获当前前台窗口，必须精确匹配非零 HWND、平台、标题、聊天类型、群发送者和客户轮次。
- 不接受缓存 OCR、屏幕截图兜底、后台窗口、窗口激活或模糊身份作为发送授权。
- 发送后只有识别到精确新增己方气泡才记 `verified`。明确未发送最多完整重试一次；`uncertain` 永不自动重发。
- 启动时把当前可见旧轮次记为 baseline；重启不能重复发送。
- “识别并处理当前聊天”按模式分流：关闭/观察只做预览，受控/全托管进入同一串行发送协调器。用户明确点击时只可事务化释放当前轮次的 startup baseline；发送中、已验证或不确定状态不能释放。
- 群聊只接受完整账号名的开头 @；未 @ 不产生回复决策。
- 第二实例由 Windows named mutex 拦截；退出停止接收新任务并排空已接受任务。

## 6. 测试、构建与数据纪律

- 功能/修复先写失败测试，再最小实现，再跑受影响测试；全量只在里程碑/最终交付跑。
- pytest 在 test collection 前自动隔离 `WECHAT_ASSISTANT_DATA_DIR`、TEMP、TMP 和 pycache，并在会话前后逐文件保护正式 AppData。
- 正式迁移已经完成；不得重复执行。未来任何正式数据迁移仍必须先停止助手、创建全目录备份并校验哈希，再做 dry-run 和原子 apply。
- staging 的免备份 apply 只允许显式数据根中的空 `memory.json`，不能指向正式目录、非空目标或其他文件名。
- 发布使用 `requirements-runtime.lock.txt` / `requirements-dev.lock.txt`，构建器不安装、不升级依赖、不覆盖同版本目录。
- 所有工作完成前只允许本地提交；用户要求最后统一 push。
- 不用 `git reset --hard` 或大范围删除恢复；保留失败制品和证据，修复版递增版本号。
