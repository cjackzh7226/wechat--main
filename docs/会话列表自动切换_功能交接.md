# 会话列表自动切换 + 会话类型四分类 — 功能交接提示词

> 本文档是给执行 agent 的交接指令。读完即可开始编码。你熟悉本项目（聊小智，企业微信客服助手），故背景从简，重点写新功能需求、约束与集成点。

---

## 一、任务目标

为聊小智 v4（企业微信 5.0.9.6060）新增两个功能：

1. **左侧会话列表自动切换**：当当前会话处理完（最新消息为我方发出）且持续稳定后，自动扫描左侧会话列表，发现红点（新消息）就点击切换到该会话，触发主程序处理。
2. **会话类型四分类**：切换到新会话后，判定对方是「个人 / 群聊 / 系统号 / 未知」四类之一，按类型分流处理。

群聊专属客服功能**本次不实现**（用户后续给需求），但群聊分支结构要预留好。

## 二、功能 1：左侧会话列表自动切换

### 2.1 触发条件（全部满足才开始扫描左侧列表）

1. 托管模式（`settings.managed_auto_reply`）开启
2. 最新消息为**我方发出**（复用现有 `latest_meaningful_message(context)` 返回 `role == "我"`）
3. 持续 **2 秒**仍为我方发出（确认稳定，不是刚发出对方又紧接着回）

→ 满足后开始扫描左侧列表，**每 2 秒一次**。

### 2.2 打断列表扫描的情况（任一发生即停止扫描/切换）

1. 最新消息变成"对方"（对方又发新消息，当前会话要重新处理）
2. 用户正在输入（焦点在输入框 + 最近 1.5 秒内有键盘活动）
3. 主路正在发送消息（`managed_send_inflight == True`）
4. 主路正在处理（`processing == True`）
5. 企业微信不在前台
6. 切换失败正在重试中

### 2.3 切换流程

1. 扫描左侧会话列表区域，用**像素颜色检测**找红点（不靠 OCR，红点是纯红色小圆点）
2. 多个红点时，选**第一个 y 最小**的（从上到下）
3. 该红点所在会话 ≠ 当前会话标识（用顶部标题文字作标识，见 2.5）
4. pyautogui 点击该行头像区（不点红点本身，太小）
5. 等待 **1.2 秒**让聊天区刷新
6. 确认切换成功：**顶部标题变化 + 红点消失** 双重确认
7. 判定会话类型（功能 2）→ 分流

### 2.4 切换失败处理

- 单次切换失败：重试 1 次
- 再失败：放弃本轮，等下一轮 2 秒扫描
- **连续 3 次失败**：弹出 UI 提示（**屏幕正中央 + 置于最上层 + 播放系统提示音**）+ 暂停旁路 5 分钟

### 2.5 当前会话标识（关键改造点）

企业微信里切换会话**主窗口 hwnd 不变**，现有 `window_key = (hwnd, title)` 去重会失效。必须新增"当前会话标识"：

- 用**顶部标题文字**（聊天窗口顶部标题栏的 OCR 文字）作会话标识
- 切换成功后更新该标识
- 扫描红点时，排除"红点所在会话 == 当前会话标识"的情况

### 2.6 切换成功后主路如何重置

切换到新会话后，主程序必须重新识别新会话内容。建议：

- 切换成功 → 设置一个 `force_refresh = True` 标志
- 下一轮 `_process_window` 以 `force=True` 跑
- 清空 `current_hash` / `current_context` / `managed_last_handled_partner` / `managed_last_handled_turn_messages` 等会话相关状态
- 重新走完整识别→生成→发送流程

**不破坏现有主路逻辑**，只通过 force 标志触发重置。

### 2.7 企业微信不在前台

- 跳过本轮，**不抢焦点**（不自动激活企业微信到前台）
- 等企业微信回到前台再恢复

## 三、功能 2：会话类型四分类

### 3.1 判定优先级

```
system（系统号）→ group（群聊）→ personal（个人）→ unknown（兜底）
```

逐级判定，命中即返回。

### 3.2 system 系统号判定（最优先）

**信号**：顶部标题 OCR 文字命中白名单或关键词。

**白名单**（基于实测截图，后续可扩展）：
- 客户联系
- 邮件提醒
- 行业资讯
- 企业微信团队
- 腾讯云企业服务
- 管理企业
- 腾讯云客服@...（前缀匹配）

**辅助关键词**（模糊匹配，命中即视为 system）：
- 团队 / 客服 / 服务 / 提醒 / 管理 / 联系

**辅助信号**：头像是单色 logo（非真人头像）。

**策略**：宁可误跳也不误回复。白名单精确匹配优先，关键词兜底。

**处理**：跳过，**不回复**。（红点切过去后自动消失，天然不循环。）

### 3.3 group 群聊判定

**核心信号**：头像 = **多个独立头像方块拼接的九宫格**（2×2 / 3×3 网格，每格是独立成员头像，格间有细分隔）。

**算法**：
1. 提取顶部标题栏左侧的头像区域（标定时确定精确坐标）
2. 把头像区域分成 3×3 子块
3. 计算每个子块的"主色"
4. 计算相邻子块之间的主色差异度
5. **差异度大**（子块边界有明显颜色跳变）→ 九宫格 → 群聊
6. **差异度小**（子块主色连续渐变）→ 单个头像 → 个人

**关键陷阱（必须避免）**：
- 单个**合影头像**（一张图里有多个人）也会色彩丰富
- **绝不能用"整体色彩丰富度"**判定，否则合影头像会误判成群聊
- 必须用"**子块边界颜色跳变**"区分：九宫格的跳变在网格边界，合影的渐变是连续的

可借鉴现有 `capture_ocr.py::_avatar_patch_score` 的色彩分析思路，但要改成"子块间差异"而非"整体方差"。

**处理**：进入群聊分支。**本次暂不回复**，UI 提示"群聊功能待补齐"。结构预留好，等用户后续给群聊客服需求时直接接入。（红点切过去后自动消失，天然不循环。）

### 3.4 personal 个人判定

**信号**：单方块头像（一个完整圆形/方形图片）。

**处理**：走现有主程序（`_process_window`）。

### 3.5 unknown 兜底

**处理**：跳过 + UI 提示"无法判定会话类型，留待人工"。

**绝不把群聊误当个人发话术**——不确定就跳过。

## 四、技术约束

### 4.1 平台与版本

- 平台：**企业微信**（`wechat_window.py::_match_platform` 已只认 wecom，微信/QQ 不处理）
- 用户版本：**5.0.9.6060**（代码注释里写的 4.x 已过时，**所有比例、颜色阈值、布局常量必须实测重定**，不能照搬旧注释）

### 4.2 关键改造点

1. **新增"顶部标题栏区域"截图 + OCR**：现有 `chat_area` 裁剪 y 从 0.10 起，**丢了顶部标题栏**。必须新增顶部区域（约 y 0~0.10）的截图与 OCR，用于：
   - 识别 system 名称
   - 提取头像做九宫格判定
   - 作"当前会话标识"

2. **新增"左侧会话列表区域"截图**：现有裁剪不含左侧列表。需新增左侧区域截图用于红点检测。

3. **会话标识改造**：用顶部标题文字替代 `window_key` 做会话去重（见 2.5）。

4. **不破坏现有主路**：新增旁路接入 `_monitor_loop`，主路（盯前台 → `_process_window`）逻辑不变，零回归。

### 4.3 资源复用建议

- 一次 `PrintWindow` 全窗截图，分别裁剪出：左侧列表区、顶部标题区、聊天对话区
- 复用同一次截图，避免重复抓屏
- OCR 引擎（RapidOCR）实例复用现有 `ChatOCR`

## 五、代码结构建议

建议新增 `conversation_list.py`，包含以下模块（类名/函数签名建议，实现自行设计）：

```python
# conversation_list.py

class ConversationListMonitor:
    """左侧会话列表扫描 + 红点检测"""
    def scan(self, full_window_image) -> list[RedDotHit]:
        """扫描左侧列表，返回红点命中列表（含 y 坐标）"""
        # 红点用像素颜色检测，不用 OCR
        # 红点 RGB 特征：R>230, G<90, B<90（标定时确认）

class ChatIdentityTracker:
    """当前会话标识（顶部标题文字）"""
    current_chat_key: str
    def update_from_top_title(self, top_title_text: str) -> None:
        """切换成功后更新当前会话标识"""

class ChatStateGuard:
    """触发/打断状态机"""
    def should_start_scan(self, latest_role: str, seconds_as_self: float) -> bool:
        """是否满足触发条件：托管模式 + 最新消息我方 + 持续2秒"""
    def is_interrupted(self, ...) -> bool:
        """6种打断情况任一命中即返回 True"""

class ConversationTypeDetector:
    """会话类型四分类"""
    def detect(self, top_title_image, top_title_text) -> ChatType:
        """返回 'personal' / 'group' / 'system' / 'unknown'"""
        # 优先级：system → group → personal → unknown

class RedDotHit:
    y: float        # 红点所在行的 y 坐标
    x_center: float # 该行中心 x（点击用）

ChatType = Literal["personal", "group", "system", "unknown"]
```

## 六、与现有代码集成点

### 6.1 `_monitor_loop`（main.py）

新增旁路，不动主路：

```
现有主路：foreground_chat() → _process_window()（不变）

新增旁路（每轮检查）：
  if 托管模式 and ChatStateGuard.should_start_scan(...):
      if ChatStateGuard.is_interrupted(...):
          skip
      else:
          hits = ConversationListMonitor.scan(全窗截图)
          if hits:
              hit = 选第一个 y 最小 且 ≠ ChatIdentityTracker.current_chat_key
              if hit:
                  切换 → 确认 → ConversationTypeDetector.detect() → 分流
```

### 6.2 切换后主路重置

切换成功后设置 `force_refresh = True`，下一轮 `_process_window` 以 `force=True` 跑，清空会话状态。

### 6.3 发送中/处理中禁止切换

`managed_send_inflight == True` 或 `processing == True` 时，旁路跳过（已列入打断条件 3/4）。

### 6.4 复用现有能力

- `ChatOCR._capture_window_bitmap`：全窗截图
- `ChatOCR.read_image` / `read_visible_text`：OCR
- `latest_meaningful_message(context)`：判断最新消息角色
- `WeChatSender._activate` / `_is_target_foreground`：窗口激活与前台判断
- `capture_ocr._avatar_patch_score`：头像色彩分析思路（九宫格算法借鉴）

跑一次企业微信，全窗截图，标定以下常量，输出成 `wecom_5_calibration.json`：

1. **会话列表区域**：左/右/上/下 坐标比例（相对窗口）
2. **顶部标题栏区域**：左/右/上/下 坐标比例
3. **头像区域**：在顶部标题栏内的位置与尺寸
4. **红点 RGB 阈值**：实测红点的 R/G/B 范围
5. **九宫格 vs 单方块头像的子块主色差异实测值**：
   - 用 personal 样本（单方块头像）和 group 样本（九宫格头像）对照
   - 算两者的 3×3 子块主色差异度，定出判定阈值

**标定样本**（用户已确认分类，基于提供的截图）：
- 第 1 条"-@微信" = **personal**（单方块头像；"@微信"是互通联系人标记，**不是群特征**）
- 第 2~8 条（客户联系/邮件提醒/行业资讯/腾讯云客服/企业微信团队/腾讯云企业服务/管理企业）= **system**
- 第 9 条"阳光，-"带"外部"标签 = **group**（九宫格头像）

## 十、注意事项与已知风险

1. **5.0.9.6060 vs 4.x**：所有比例、颜色、布局常量必须实测重定，不能照搬代码里 4.x 的注释。
2. **九宫格检测的最大陷阱**：合影头像 vs 九宫格拼接。必须用"子块边界颜色跳变"区分，不能用整体色彩丰富度。
3. **system 白名单可能不全**：用关键词兜底，宁可误跳也不误回复。
4. **切换会抢占前台**：靠"用户输入暂停"等 6 种打断条件保护。
5. **同窗口切会话 hwnd 不变**：必须用顶部标题文字作会话标识，不能用 hwnd。
6. **红点切过去后自动消失**（5.0.9.6060 实测）：天然避免群聊/system 死循环，无需额外处理。
7. **群聊分支结构预留**：本次暂不回复，但类/分支结构要预留好，方便后续接群聊客服功能。
8. **打包纪律**（用户要求）：本次开发用源码（`启动.bat` / `.venv`）验证即可，**不要每次都打包新 EXE**。需要打包时直接在 `dist\聊小智_开发测试_20260803_v4\聊小智\` 上覆盖更新，不新建版本目录。
9. **不改用户数据**：不覆盖 `%APPDATA%\WeChatStyleReplyAssistant\settings.json`、`memory.json`、`vector_memory.json`。
