# 企业年报知识库设计

## 目标

让程序在任意电脑上导入具有“模块、机构类型、问题、答案”结构的企业年报 Excel 时，自动解析为可追溯的专属知识库；面对同义问法时，先召回候选，再让已配置的大模型只负责排序，最后原样返回经过确认的知识库答案。

## 约束

- 不以电脑用户名、文件绝对路径或文件名作为识别条件。
- 不改变原始 Excel，也不要求用户改成固定模板。
- 新逻辑只依赖 Python 标准库，便携包无需额外安装 Excel 解析依赖。
- 普通聊天记录和既有话术库导入行为保持不变。
- 企业年报答案属于权威原文：高置信命中时不得由大模型改写、补写或截断。

## 架构

新增 `enterprise_kb.py`，负责识别和解析复杂 `.xlsx` 工作簿。它读取 XLSX 内的 XML、共享字符串、工作表和合并单元格，恢复每个单元格的真实坐标；通过“模块”表头、至少一个机构类型列、以及多条 `问题…答…` 单元格共同判断是否为企业年报知识库。

解析结果为标准训练样例，同时携带 `module`、`subcategory`、`organization_type`、`source_sheet`、`source_cell` 和 `source_file`。`chat_training.py` 在通用解析前调用该识别器；只有成功识别时才写入独立来源 `enterprise_annual_report_kb`。

`memory.py` 提供企业知识库候选召回，保留原有关键词和稀疏向量结果，但只对企业来源返回候选。`reply_engine.py` 对候选问题进行大模型重排：请求只包含当前问题、候选编号、问题和分类，不包含答案；模型仅返回 JSON 编号和置信度。通过本地最低相关性和模型置信度双阈值后，程序原样返回对应答案；否则回到现有普通回复流程。

## 数据流

1. 用户在任意电脑的“导入话术”选择 Excel。
2. 导入器检测结构，解析合并的模块/子模块及每个机构类型列中的问答。
3. 导入器为每条问答建立可检索上下文，并保存来源单元格。
4. 对话发生时，程序先从企业年报库召回最多 6 条候选。
5. 有 API Key 时，大模型只负责候选排序；无 Key 或排序失败时保留现有本地检索/常规回复降级路径。
6. 双阈值通过时，显示一条完整原始答案，并显示“企业年报知识库”及来源；普通聊天继续使用现有短回复规则。

## 安全与稳定性

- 识别必须同时满足结构特征和有效问答数量，防止普通 Excel 被误判。
- 空导入或解析失败不得删除已有企业年报知识库。
- 重新导入有效企业年报库时，仅原子替换同一企业来源，不覆盖普通聊天话术。
- 低置信度时不伪造“知识库答案”；由现有流程处理，并保留来源状态。
- 对超长权威答案不做字符截断；用户仍可在现有编辑框中人工缩短后发送。

## 验收标准

- 对提供的年报工作簿解析出 90 条问答，其中社会团体 74 条、民办非企业单位 16 条。
- 每条均保存模块、机构类型、工作表和单元格来源。
- 与问题措辞不同但语义相近的输入能由候选重排选择正确官方答案。
- 低置信选择不会直接发送错误的知识库答案。
- 原有 200 项测试以及新增解析、重排、降级测试通过。
- 新便携包可在未安装 Python/Excel 的同事电脑上导入同类 Excel。
