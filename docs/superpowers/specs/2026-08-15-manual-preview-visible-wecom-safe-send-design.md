# 手动预览与可见企业微信安全发送设计

日期：2026-08-15
状态：用户已确认

## 1. 背景与根因

聊小智与企业微信并排显示时，用户点击“识别当前聊天”，Windows 会把聊小智设为唯一前台窗口。现有托管逻辑把“窗口可见”“窗口处于前台”“允许发送”混成一个条件，并让手动识别复用自动发送路径，因此出现以下错误行为：

- 手动识别找不到仍然可见的企业微信；
- 切换会话后能短暂识别，但聊小智重新获得焦点后 UI 又回到“等待聊天窗口”；
- 群聊 OCR 已成功，却继续进入发送预检并显示“群聊发送前实时识别失败”；
- `observe` 模式本来不发送，却显示“托管发送暂停”等误导信息。

严格发送复核仍然必要，但必须与无副作用的手动预览彻底分离。

## 2. 已确认目标

1. 点击“识别当前聊天”只执行 OCR、问题提取、知识库匹配和候选展示，任何模式下都不得自动发送。
2. 企业微信可见且未最小化时，即使聊小智获得焦点，也可以完成手动识别。
3. `observe` 只预览，不激活企业微信、不创建发送任务、不写发送台账。
4. `controlled/full` 的后台自动流程可以识别可见的企业微信；需要发送时，程序可短暂激活已经复核的企业微信窗口。
5. 真实发送前后继续执行严格的窗口、会话、发送者、问题、答案和气泡验证。
6. 已识别的标题、上下文和候选不得被普通 idle 轮询清空或覆盖成“等待聊天窗口”。

## 3. 非目标

- 不放宽知识库合同：只有 `active` 记录可用于托管答案，模型仍只允许排序或一致性判断。
- 不允许后台生成或改写答案；无可靠命中仍使用精确固定答复“暂未查到对应答案”。
- 不允许在用户正在操作浏览器、文档等第三方程序时强行抢焦点发送。
- 不修改正式知识库数据，不在本设计阶段执行正式发送或发布。

## 4. 术语与窗口状态

- **可见窗口**：HWND 有效、窗口可见、未最小化；不要求当前获得键盘焦点。
- **前台窗口**：Windows 当前唯一接收键盘输入的窗口。
- **聊小智前台**：用户正在操作聊小智；允许手动预览，也允许受控自动流程在发送瞬间激活已复核的企业微信。
- **企业微信前台**：可直接进入发送前复核。
- **第三方窗口前台**：浏览器、文档等非聊小智、非目标企业微信窗口；自动流程不得抢焦点。

## 5. 架构

### 5.1 手动预览链

新增独立的手动预览协调路径，不构造发送适配器，不调用托管工作线程，不接触发送器或发送台账。

数据流：

1. 选择目标：前台企业微信优先；否则使用当前仍有效且可见的企业微信；再否则发现一个可见企业微信窗口。
2. 通过目标 HWND 直接截图，识别顶部标题、会话类型和聊天上下文。
3. 群聊提取最新发送者、@ 当前账号的问题；个人聊天提取当前未回复问题。
4. 调用统一的无副作用知识决策接口，只读取已批准知识记录。
5. 将上下文、候选、来源和“仅预览、未发送”状态发布到 UI。
6. 结束。不得调用自动发送、发送预检、发送台账或气泡验证。

### 5.2 后台自动发送链

后台监控可以对可见且未最小化的企业微信进行只读 OCR，但发送权限与识别权限分开判断。

数据流：

1. 捕获目标 HWND，建立包含 HWND、平台、规范化标题、会话类型、发送者、问题指纹和上下文哈希的观察对象。
2. 从 `active` 知识记录中得到答案，并在发送前再次确认答案仍然有效。
3. 检查当前前台窗口：
   - 目标企业微信：继续；
   - 聊小智：允许激活已复核的目标企业微信；
   - 第三方窗口：暂缓本轮，不激活、不发送、不写终态。
4. 激活目标企业微信后，再次截取同一 HWND，并逐项复核标题、类型、发送者、问题指纹和上下文。
5. 复核完全一致后才准备发送台账并执行一次发送。
6. 发送后识别我方新气泡；验证成功记录 `verified`，无法确认记录 `uncertain` 并禁止自动重试，明确未发送才允许受限重试。

### 5.3 共享能力

两条链只共享以下无副作用能力：

- 窗口有效性与可见性检查；
- 指定 HWND 截图；
- OCR 与会话类型识别；
- 发送者、@ 提问和个人未回复轮次提取；
- 知识库候选查询与决策。

任何包含激活、鼠标键盘输入、发送台账写入或气泡验证的能力只能由后台自动发送链或用户明确点击“发送到当前聊天”调用。

## 6. UI 状态合同

### 6.1 手动预览

- 开始：`正在识别当前聊天…`
- 命中：`已生成候选回复，仅预览，未发送`
- 未命中：候选区显示 `暂未查到对应答案`，状态仍明确“仅预览，未发送”
- 群聊无 @：`已识别群聊；最新消息未 @ 当前账号，不生成候选`
- OCR 失败：`未识别到聊天内容，请确认企业微信窗口可见且未最小化`
- 知识决策异常：显示“匹配暂不可用，未发送”，不得显示发送失败

### 6.2 自动流程

- `observe`：只显示观察决策，不显示前台或发送失败类提示。
- `controlled/full` 且聊小智前台：可以在发送瞬间激活已复核企业微信，不显示“企业微信不在前台”。
- 第三方窗口前台：`检测到你正在使用其他窗口，本轮暂不发送`。
- 激活后复核失败：`会话或问题已变化，本轮未发送`。
- 已识别的聊天标题、上下文和候选保持可见；普通 idle 事件不能清空它们。

## 7. 安全不变量

1. 手动“识别当前聊天”调用发送器次数必须恒为 0。
2. `observe` 模式调用窗口激活、发送器和发送台账写入次数必须恒为 0。
3. 自动发送只能针对最初观察和激活后复核均一致的同一非零 HWND。
4. 第三方窗口处于前台时，不得激活企业微信或发送。
5. 任何标题、聊天类型、发送者、问题或答案变化都必须在按键前阻断。
6. 一个 turn key 在待处理期间只能进入队列一次。
7. 未观察到正确的新我方气泡时，不得记录为已验证发送。

## 8. 测试设计

### 8.1 手动预览

- 个人聊天与群聊均能在聊小智前台、企业微信侧边可见时识别。
- 个人聊天与群聊的手动识别均不会调用托管工作线程、发送器或发送台账。
- 群聊发送者昵称行不会进入问题正文。
- 群聊无 @、知识未命中、接口异常分别显示准确的预览状态。
- idle 轮询不会清空已识别标题、上下文或候选。

### 8.2 自动发送

- 企业微信已在前台：复核后发送一次。
- 聊小智在前台且企业微信可见：激活精确 HWND、再次复核、发送一次。
- 第三方窗口在前台：激活 0 次、发送 0 次、台账无误导终态。
- 目标窗口最小化、不可见或 HWND 失效：发送 0 次。
- 激活后标题、聊天类型、发送者或问题变化：发送 0 次。
- `observe`：激活 0 次、发送 0 次、台账写入 0 次。
- 同一轮次并发入队只接受一次。
- 发送后 `verified / uncertain / not_sent` 三种结果按既有台账合同处理。

### 8.3 现场验收

1. 聊小智和企业微信并排显示，直接点击“识别当前聊天”，确认上下文和候选稳定保留且无发送错误。
2. `observe` 下发送一条 active 知识问题，确认只产生一条 `observe_only` 且 `sent=false`。
3. `controlled` 下仅允许指定测试群，聊小智处于前台时触发一条新问题，确认程序只激活指定企业微信、复核后发送一次并验证气泡。
4. 把第三方窗口置于前台，确认不抢焦点、不发送。

## 9. 实施与回滚边界

- 严格按测试先行实施：先证明现有手动识别会误入发送链，再拆分路径。
- 每个行为边界单独 RED→GREEN，之后运行托管、群聊、OCR、持久化和完整测试套件。
- 正式 AppData 继续只读保护，运行时使用隔离 staging 数据。
- 不在本阶段 push；完成全部验收、开发日志和发布制品后再统一提交与推送。
- 若现场受控发送无法满足任一安全不变量，保持 `observe`，不得进入正式自动发送。
