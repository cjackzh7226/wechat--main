# 企业年报知识库检索与最终回复设计

## 目标

让企业年报知识库的“测试命中”和实际自动回复使用同一套排序；模糊问法在本地高置信时直接返回知识库原答案；无法可靠匹配时直接说明未找到答案；自动发送不再发送或补发“我先看一下、稍后回复”等过渡话术。

## 根因

测试界面调用通用 `scored_examples`，运行时调用独立的 `enterprise_candidates`。两套评分规则对“怎么查以前的年度报告”给出不同第一名：前者为 C11，后者为 C15。运行时又要求非精确匹配必须有可用大模型复核；未配置 Key 时会落入普通本地兜底话术。自动发送随后把这类未完成式话术视为需要补全，继续发送过渡句和核实承诺。

## 设计

1. `StyleMemory.enterprise_candidates` 成为企业年报唯一的排序入口，并加入时间、动作和主题的同义意图特征。历史查询与“本年度填报/修改”等冲突意图会被降权。
2. 新增企业年报测试展示适配器，测试界面直接展示上述候选及其评分、原因，禁止再次使用通用话术库评分。
3. 第一名满足高分、无冲突且领先第二名足够明显时，回复引擎直接返回其原始知识库答案，不要求 API Key；精确问题仍直接返回。
4. 已识别为企业年报问题但未可靠匹配时，统一返回“未在当前企业年报知识库中找到对应答案。”；普通问题若只剩过渡候选，则统一返回“暂时未查到对应答案。”。
5. 自动发送仅发送最终答案；过滤未完成式候选并删除自动补全/诚实兜底补发链路。

## 边界

- 不修改已导入的 Excel 或用户数据。
- 不增加第三方模型或依赖；无 API Key 时仍可处理高置信模糊匹配。
- 不生成便携版或压缩包。

## 验收

- “怎么查以前的年度报告”“年报历史记录在哪里能看到”等问法命中 C11 的原始答案。
- 测试界面与运行时的企业年报第一名一致。
- C15 的“本年度已存在/修改填写”不会匹配为历史报告查看。
- 自动回复不会发送任何“我先看、核实、稍后”等过渡内容；不能可靠回答时只发送明确未命中句。
