# 知识库候选核验修复

部分已入库问答在运行时显示“未在当前企业年报知识库中找到对应答案”，有三个不同原因：实际答案未进入模型候选、答案核验被截断或限制在标题同义判断、接口失败被当成未命中。

## 已复现

- 使用仓库随附的 449 条企业知识库，对“负责人超龄怎么整改”检索时，年龄超 70 周岁条目排第 5；旧程序只传前三名，遗漏正确条目。
- 该示例库中 182 条答案超过 150 字；旧核验请求统一截取前 150 字，后续情形和材料要求不可见。
- 用户提供的“负责人超过理事数的1/3”纳入回归：允许直接陈述问题，核对原答案完整保留“情形二”等内容，并与常务理事数 1/2 条目区分。
- 接口超时、无 Key 或输出不是有效 JSON，旧流程都返回知识库未命中文案；群聊还可能发送该文案。

## 行为变化

- 保留原有精确问题直接返回原答案的规则，以及本地 30 分准入规则。非精确命中统一提交同一次检索中最多 6 个有意义、无本地时间/操作冲突的候选；第一名领先也保留其他候选。
- 核验请求包含完整答案和机构类型等分类信息，检查答案能否直接覆盖客户需求，允许口语、简称和答案已经包含的子问题。不同时间、操作、对象、数值或不满足的业务条件仍须拒绝。
- 模型只能返回候选编号和适用性，最终回复始终读取该条知识库原答案，不采用模型编写的答案。
- 技术失败返回空候选并显示错误，群聊停止发送；成功核验后认为答案不适用时仍保留未命中文案。

## 验证与边界

回归覆盖完整答案传递、示例库第五名选择、第一名领先时保留其他候选、无 Key/超时/异常 JSON/非法编号、冲突候选排除以及群聊失败时不发送。模型响应使用测试替身，用于验证请求和程序行为，不能代表用户实际 API 对所有问法的判断效果；未使用用户真实 Key，未发送真实聊天消息。

本次不修改用户知识库或配置。更新包只替换程序，沿用安装前备份全部 user_data、安装后逐文件校验的保护流程。
