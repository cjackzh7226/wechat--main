# 群聊客服功能分支 — 功能交接提示词

> 本文档是给执行 agent 的交接指令，是 `docs/会话列表自动切换_功能交接.md` 的续篇。前置文档里的"四分类判定"完成后，判定为 `group` 的会话进入本文档描述的群聊客服分支。你熟悉本项目，故背景从简。

## 一、任务目标

为聊小智 v4（企业微信 5.0.9.6060）实现**群聊专属客服功能**：

- 当四分类判定当前会话为**群聊**时，进入群聊客服分支
- 群聊里只有**对方消息开头 @ 了当前账号用户名**，才列为"对方问题"走回复流程
- 没 @ 的消息忽略不回答，认定为"聊天内容无变化"
- 回复时**文字 @ 回提问者**（`@提问者名字 回复内容`）
- 复用现有话术库/企业库/知识库

**前置依赖**：`docs/会话列表自动切换_功能交接.md` 的四分类判定（`ConversationTypeDetector` 返回 `group`）。

## 三、群聊客服核心逻辑

### 3.1 进入条件

四分类判定（`ConversationTypeDetector.detect()`）返回 `group` → 进入群聊客服分支。

### 3.2 @ 识别与判定

**群聊消息格式**（基于实测截图）：
```
[发送者名字(灰色)] [平台标记(绿色，如@微信)]
    @程正恒 问题内容          ← @ 我的消息（黑色文字）
    你好                       ← 没 @ 我的消息
```

**判定规则**：
1. 取最新一条**对方消息**（`role == "对方"`）
2. 检测该消息**开头**是否为 `@` + 当前账号用户名
3. **@ 在消息第一个字符**才算（消息中间的 @ 不算）

**示例**（用户名="程正恒"）：
| 消息内容 | 判定 | 处理 |
|---|---|---|
| `@程正恒 民非单位未按规定换届怎么整改` | ✅ @ 我 | 走回复流程 |
| `民非单位未按规定换届怎么整改` | ❌ 没 @ | 忽略，认定"聊天内容无变化" |
| `你好 @程正恒` | ❌ @ 不在开头 | 忽略，认定"聊天内容无变化" |
| `@程正恒：你好` | ✅ @ 我（容错匹配） | 走回复流程 |

### 3.3 @ 匹配容错

OCR 可能识别出 `@程正恒` / `@程正恒：` / `@程 正恒` / `@程正恒 ` 等变体。匹配规则：
1. 去掉消息开头的 `@`
2. 去掉空格、标点（`：:，,、` 等）
3. 与用户名（同样去空格标点后）比较
4. 相同 → 判定 @ 我

### 3.4 "对方问题"提取

@ 我的消息，去掉开头的 `@用户名` 前缀（含可能的空格/标点），剩余部分作为**真正的问题**交给话术库/模型。

- `@程正恒 民非单位未按规定换届怎么整改` → 提取 `民非单位未按规定换届怎么整改`
- `@程正恒：你好` → 提取 `你好`

### 3.5 发送者名字识别（用于 @ 回去）

**目标**：从 @ 我的那条消息里识别**发送者名字**，回复时 `@发送者名字 回复内容`。

**群聊消息布局**（基于实测截图）：
- 发送者头部 = 灰色名字 + 绿色平台标记（如 `阳光@微信`、`-@微信`）
- 平台标记是绿色的（`@微信`、`@-@微信`、`(微信)`、`·微信` 等），**不是名字的一部分**

**识别算法**：
1. OCR 识别发送者头部整段文字（灰色名字 + 绿色平台标记）
2. 用字符串规则**去掉平台标记后缀**：
   - 去掉尾部 `@-@微信`、`@微信`、`(微信)`、`·微信`、`(企业微信)` 等
   - 去掉首尾空格、特殊符号（`-`、`·` 等孤立符号）
3. 剩余部分即为发送者名字

**示例**：
| OCR 识别的头部 | 处理后名字 |
|---|---|
| `阳光@微信` | `阳光` |
| `-@微信` | `-`（或视实际名字） |
| `张三(企业微信)` | `张三` |

> 注意：用户要求"识别对方的名字要准确点"，所以平台标记去除规则要覆盖企业微信 5.0.9 的所有常见变体，标定时实测补全。

### 3.6 回复格式与发送

- **文字 @**（不是真 @ 提醒，不模拟 @ 选择器）
- 回复内容 = `@发送者名字 ` + 话术库/模型生成的回复
- 复用现有 `sender.py::WeChatSender.send()` 发送

**示例**：
- @ 我的消息：`@程正恒 民非单位未按规定换届怎么整改`
- 发送者：`阳光`
- 模型生成的回复：`民非单位未按规定换届，应当...`
- 最终发送：`@阳光 民非单位未按规定换届，应当...`

### 3.7 话术来源

**复用现有**：企业库（`enterprise_candidates`）→ 话术库（`phrasebook_candidates`）→ 模型 → 知识库 → 兜底规则。与个人聊天走同一套 `reply_engine.generate()` 决策链。

## 四、触发列表扫描条件扩展

### 4.1 个人聊天（不变）

托管模式 + 最新消息为我方发出 + 持续 2 秒 → 扫描左侧列表。

### 4.2 群聊（新增）

群聊里"最新消息没 @ 我"= **聊天内容无变化**，等同于"我方发出"的待遇，也能触发列表扫描：

```
托管模式 + (
    最新消息为我方发出
    OR
    (群聊 AND 最新消息为对方 AND 没有开头@我 = 聊天内容无变化)
) + 持续 2 秒 → 扫描左侧列表（每 2 秒一次）
```

**关键区分**：
- "最新消息为我方发出" = 已处理完 → 触发扫描
- "群聊最新消息没@我" = 不需要处理 → 触发扫描
- "群聊最新消息@我" = 有对方问题要回答 → **不触发扫描**，走回复流程

### 4.3 @ 被覆盖边界（已确认接受）

有人 @ 我问问题，我还没回复，另一个人发了没 @ 的消息 → 最新消息变成没 @ 的 → 按"最新消息为准"认定"无变化"→ 去扫描列表 → **@ 我的问题被漏掉**。

用户已确认接受此行为（实际群聊里 @ 我后会很快回复，被覆盖概率低）。

## 五、群聊 OCR 轮询间隔

### 5.1 间隔调整

- 现有默认：`poll_interval_ms = 1200`（1.2 秒）
- **群聊会话时**：缩短为 **800ms**（0.8 秒），让 @ 消息响应更快
- 个人聊天/系统号/未知：维持 1200ms

### 5.2 实现

- 新增 settings 字段：`group_poll_interval_ms: int = 800`
- `_monitor_loop` 里根据当前会话类型动态选择间隔：
  - 当前会话为 `group` → 用 `group_poll_interval_ms`
  - 其他 → 用 `poll_interval_ms`

## 六、边界与异常处理

### 6.1 用户名为空时

- 群聊会话 + 用户名为空 → **弹提示让用户填写**（首次）
- 填写前：群聊消息全部视为"聊天内容无变化"（不回复，直接触发列表扫描）
- 填写后：正常走 @ 识别逻辑

### 6.2 群聊里"我方发出"判定

- 群聊里我发的消息，OCR 判角色为"我"（复用现有 `latest_meaningful_message`）
- 我方发出 → 持续 2 秒 → 触发扫描列表（与个人聊天一致）

### 6.3 群聊系统消息

- "你邀请微信的-、阳光加入了外部群聊"、"填写群名称，方便维护和管理"等系统提示
- 现有 `_is_noise_text` / `_is_system_message_text` 应能过滤
- 标定时验证群聊系统消息是否被正确过滤

### 6.4 群聊 emoji/表情消息

- 没 @ 我的 emoji → "聊天内容无变化" → 不回复
- 现有 `visible_content.py` 的 sticker/emoji 处理可复用

### 6.5 多条 @ 我连续来

- 只处理**最新一条** @ 我的消息（"最新消息为准"原则）
- 回复后最新消息变我方发出 → 触发扫描列表

### 6.6 群聊里 @ 我 + 左侧红点同时存在

- @ 我 = 有对方问题要回答 → 不触发列表扫描（打断条件"最新消息为对方"生效）
- 回复完 → 最新消息变我方发出 → 2 秒后才扫描列表

## 七、代码结构建议

建议新增 `group_chat_handler.py`：

```python
# group_chat_handler.py

class GroupChatHandler:
    """群聊客服处理器"""

    def __init__(self, settings: AppSettings):
        self.settings = settings

    def detect_at_mention(self, context: str, account_name: str) -> bool:
        """检测最新对方消息开头是否 @ 了当前账号用户名
        - 取最新一条 role=="对方" 的消息
        - 检测开头是否为 @ + 用户名（容错匹配）
        - 返回 True/False
        """

    def extract_question(self, message: str, account_name: str) -> str:
        """从 @ 我的消息里提取真正的问题内容
        - 去掉开头的 @用户名 前缀（含空格/标点）
        - 返回剩余文本
        """

    def extract_sender_name(self, context: str) -> str:
        """从 @ 我的消息里识别发送者名字
        - OCR 识别发送者头部（灰色名字 + 绿色平台标记）
        - 字符串规则去掉平台标记后缀
        - 返回纯名字
        """

    def build_reply(self, sender_name: str, reply_content: str) -> str:
        """构建回复内容
        - 格式：@发送者名字 回复内容
        - 返回完整回复字符串
        """

    def is_chat_idle(self, context: str, account_name: str) -> bool:
        """判断群聊是否处于"聊天内容无变化"状态
        - 最新消息为对方 且 没有开头@我 → True（可触发列表扫描）
        - 用于扩展触发列表扫描条件
        """
```

### 8.2 群聊分支处理流程

```
进入群聊分支:
  1. account_name = settings.wecom_account_name
  2. if not account_name:
       弹提示让用户填 → 填前视为"聊天内容无变化"
  3. context = ChatOCR.read_image(聊天区截图)
  4. latest_role = latest_meaningful_message(context).role
  5. if latest_role == "我":
       → 我方发出 → 持续2秒 → 触发列表扫描（与个人一致）
  6. elif latest_role == "对方":
       if GroupChatHandler.detect_at_mention(context, account_name):
         question = extract_question(最新对方消息, account_name)
         sender = extract_sender_name(context)
         reply = reply_engine.generate(question)  # 复用现有决策链
         final_reply = build_reply(sender, reply)
         sender.send(wechat, final_reply)
         → 回复后最新消息变我方发出 → 触发列表扫描
       else:
         → 聊天内容无变化 → 持续2秒 → 触发列表扫描
```

### 8.3 触发列表扫描条件扩展

在 `ChatStateGuard.should_start_scan()` 里新增群聊分支：

```python
def should_start_scan(self, latest_role, chat_type, account_name, context, seconds_stable):
    if not self.settings.managed_auto_reply:
        return False
    if chat_type == "group":
        # 群聊：我方发出 OR 聊天内容无变化（没@我）
        if latest_role == "我":
            return seconds_stable >= 2.0
        if latest_role == "对方" and not detect_at_mention(context, account_name):
            return seconds_stable >= 2.0
        return False
    else:
        # 个人/其他：仅我方发出
        return latest_role == "我" and seconds_stable >= 2.0
```

interval = (self.settings.group_poll_interval_ms

## 十二、注意事项与已知风险

1. **@ 是黑色文字**（用户已确认，非蓝色），OCR 识别无障碍。但仍需标定验证。
2. **发送者名字识别准确性**：用户特别要求"识别对方名字要准确点"。平台标记后缀去除规则必须覆盖企业微信 5.0.9 所有变体，标定时补全。
3. **文字 @ 非真 @**：回复用纯文字 `@发送者名字 回复内容`，不模拟 @ 选择器，对方不会收到 @ 红点提醒。用户已确认接受。
4. **@ 被覆盖会漏**：@ 我后被非@消息覆盖，按"最新消息为准"会漏掉。用户已确认接受。
5. **群聊 OCR 间隔 800ms**：比个人聊天快，注意 OCR 引擎负载。若 RapidOCR 扛不住，回调到 1000ms。
6. **右侧群成员面板不一定可见**：自动检测"我"名字是备用来源，面板不可见时由用户手动填。
